## SQL 验证流程重构：从只读查询到语义测试验证

### 背景
- 用户要求：LLM 应根据需求语义生成测试 SQL（包括 DDL 如 CREATE TABLE），预判期望输出，然后调用 MCP 验证
- 原流程：仅允许 SELECT/EXPLAIN 等只读查询，无法验证 DDL 特性（如 ON UPDATE CURRENT_TIMESTAMP）

### 修改内容

18. **改写 `sql_validator.py`** - 新增测试模式
    - 新增 `TEST_ALLOWED_SQL_PREFIXES`：允许 CREATE/ALTER/DROP/INSERT/UPDATE/DELETE/SET/BEGIN/COMMIT/ROLLBACK
    - 新增 `TEST_TABLE_PREFIX = '_mcp_test_'`：所有测试表名必须以此前缀开头
    - 新增 `validate_test_sql_safety()`：测试模式安全校验，DDL/DML 必须操作 _mcp_test_ 前缀的表
    - 新增 `execute_test_sql_safely()`：按顺序执行一组 SQL 语句，自动收集并清理测试表
    - 新增 `execute_test_sql_on_all()`：在所有启用的数据库上并行执行测试 SQL 组
    - 新增 `format_test_results_for_llm()`：格式化测试模式的多数据库结果

19. **改写 `function_tools.py`** - 新增 execute_sql_test 工具
    - 新增 `execute_sql_test` tool schema：接收 sql_statements(数组)、db_types、expected_behavior
    - 新增 `_execute_sql_test_tool()` 执行函数
    - 注册到 `_TOOL_EXECUTORS` 中

20. **改写 `mcp_server.py`** - 新增 execute_sql_test MCP 工具
    - 新增 `@mcp.tool() execute_sql_test()` 函数
    - 更新 `sql_analysis_prompt` 提示词模板

21. **重写 `_process_sql_requirement()`** - 核心方法重构
    - 新 system prompt：5步流程（需求分析→设计测试SQL→预判期望输出→调用工具验证→分析总结）
    - 工具调用从 `execute_sql` 改为 `execute_sql_test`
    - 结果解析兼容 test_results 和旧格式
    - 置信度从 0.7 提升到 0.8（因为有实际 DDL 验证结果）

22. **更新 Skills 模板** (`sql/update_sql_extraction_template.sql`)
    - 数据库中 `sql_extraction` 场景的默认 prompt 更新为新的5步流程模板
